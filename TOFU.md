# Tofu gallery copy

This repository is Tofu's copy of **requarks/wiki-v2** (licence: AGPL-3.0), listed in Tofu's app gallery as **Wiki.js**: a wiki for a team or a family. Pages are written in Markdown or a visual editor, kept in a page tree with a sidebar and tags, found with search, and have their own history, comments and per-group permissions.

- `main` mirrors the upstream repository and is never committed to by Tofu.
- `tofu` carries Tofu's own changes; tags named `pin/<date>` mark the versions the gallery points to. The current pin is `pin/2026-10-25.1`.
- A visitor who chooses this app gets a private snapshot of the pinned version in their own Tofu account. Their copy does not follow upstream updates.
- Upstream: https://github.com/requarks/wiki-v2 at `bd602f7e667728d5256316f9eddcd096569fc6ce`, the v2.5.317 release (2026-10-23). Wiki.js 2's code lives in `requarks/wiki-v2`; `requarks/wiki` holds the next major version.

## How Tofu runs it

- Framework preset `container`, root folder: the repository root. Tofu builds the root `Dockerfile` and runs the image as a service, so there is no separate install command, build command or output directory.
- The `Dockerfile` is upstream's `dev/build/Dockerfile`, in two stages:
  - The assets, on `node:24-alpine` with `yarn g++ make cmake python3`: `yarn --frozen-lockfile --non-interactive`, then `yarn build` (webpack, which writes `assets/` and the generated views `server/views/master.pug`, `setup.pug` and `legacy/master.pug`), then a production-only install and `yarn patch-package`.
  - The image, on `node:24-alpine` with `bash curl git openssh gnupg sqlite`: the assets, `node_modules`, `server`, the generated views, `dev/tofu/config.yml` as `config.yml`, `dev/tofu/sideload` as `data/sideload`, `package.json` and `LICENSE`. It starts `node --no-deprecation server`, as root.
- Port: `PORT`, which Tofu sets; 3000 without it.
- Database: PostgreSQL, the copy's Tofu database, read from `DATABASE_URL` (`server/core/db.js` reads it ahead of the `db` section of `config.yml`). Wiki.js makes its own tables when it starts, with its knex migrations (`server/db/migrations`), and two more, `sessions` and `brute`, when its server first starts past the setup, so there is no `supabase/migrations` folder and Tofu applies nothing before the build.
- Settings: Tofu sets `PORT` and `DATABASE_URL` (and `SUPABASE_URL`, `SUPABASE_ANON_KEY` and `SUPABASE_CA_CERT`, which Wiki.js does not read). The gallery saves `SOURCE_URL`, this pin's own source, before the first deploy. The owner saves `ADMIN_PASSWORD` as a hidden value (see "The first administrator"). Nothing else has to be set. An owner may set any other `$(NAME)` in `dev/tofu/config.yml`, such as `LOG_LEVEL`, `DB_SSL_CA` or `WIKI_OFFLINE`.
- Secrets: at its setup Wiki.js makes its own session secret and the key pair that signs sign-ins, and keeps them in the database (`settings`). A copy needs no secret setting besides `ADMIN_PASSWORD`, which is read only until the setup is finished. Restarts and redeploys leave sign-ins alone.

## What Tofu changes

Every commit on `tofu` starts with `Tofu:` and says why. Every changed upstream file carries a dated `Tofu (2026-10-25)` notice at the change, except `package.json`, which cannot hold a comment and is described here. Tofu's own new files say so at their top.

- `package.json`: `"version": "2.5.317"` and `"dev": false`. Upstream's repository keeps `2.0.0` and `"dev": true`, and its release workflow rewrites both with `jq` before it builds the image. Tofu builds from the repository, so the release values live in the file.
- `Dockerfile` and `.dockerignore` (new). Upstream's `dev/build/Dockerfile` (unchanged, and still what upstream's own images are built from), with these differences:
  - `yarn.lock` is copied into the assets stage, so `--frozen-lockfile` holds the install to the lockfile's versions. Upstream's stage copies no lockfile.
  - No `USER node`. Tofu gives the container `PORT=80` unless the app sets another, and only root may listen on a port below 1024. No `VOLUME`: no disk outlives a restart on Tofu.
  - Tofu's `config.yml` and the English interface (below).
- `dev/tofu/config.yml` (new). Upstream's `dev/build/config.yml` with defaults, so a copy starts from `PORT` and `DATABASE_URL` alone: `port: $(PORT:3000)`; `db.type: $(DB_TYPE:postgres)` (upstream's has no default, and an unset `DB_TYPE` would be read as the word `undefined`); `DB_SSL`, `SSL_ACTIVE` and `HA_ACTIVE` off; and `offline: $(WIKI_OFFLINE:true)`. Offline is Wiki.js's own mode for a server that does not reach upstream's `graph.requarks.io`: no telemetry, no daily update check, no locale download.
- `dev/tofu/sideload` (new): `en.json` and `locales.json`, unchanged from https://github.com/Requarks/wiki-localization at `6b0826df8e7a0c25841102a68184f61e5a81e1c1` (AGPL-3.0, like Wiki.js; `dev/tofu/sideload/SOURCE.md`). Wiki.js 2 keeps no interface words in its own repository: online, it downloads them, English included, from `graph.requarks.io` at every start and every day. Offline, `server/core/sideloader.js` imports them from `data/sideload` at every start, so the copy's interface has its English words without reaching upstream.
- `server/core/db.js`, `DATABASE_URL`'s `sslmode`. Tofu's `DATABASE_URL` ends in `?sslmode=require`. Upstream hands the URL to knex as it is, and knex 0.21's URL parser (pg-connection-string 2.3.0) does not know `sslmode`, so the connection went without TLS, and a server that requires TLS refused it. Handing the URL to node-postgres itself would fail too: it treats `require` as full certificate verification, which fails against a managed database's pooler. When the URL names an `sslmode`, it is now taken out and TLS is set as libpq means it: `disable` is off, `verify-ca` and `verify-full` verify the server's certificate, and `require` (and `prefer`, `allow`) encrypts without verifying it. `DB_SSL_CA` still verifies against its certificate, now with `DATABASE_URL` too. Nothing depends on the database's host name.
- `server/db/tofu-data-api.js` (new), `server/core/db.js`, `server/master.js`, `server/controllers/auth.js` and `server/modules/search/postgres/engine.js`, row-level security. Tofu's databases are Supabase PostgreSQL, and a database whose default privileges still give every new table in `public` to the Data API's roles (`anon`, `authenticated`) would let anyone with the project's public key read and change Wiki.js's tables through the Data API: `users` with its password hashes, `settings` with the key that signs sign-ins, `sessions` with sign-in state (OAuth state, sign-in ids, ID tokens), `brute` with the counters that lock out password guessing on `/login`, `/verify` and `/login-reset`, every page. Wiki.js turns on row-level security, with no policy, on each of its own tables that its role owns and that does not have it yet:
  - after its migrations, at every start: the 28 tables its migrations make, knex's `migrations` and `migrations_lock`, and whichever of the tables below exist by then;
  - `sessions` (the session store's, `connect-session-knex`) and `brute` (the sign-in lockout's, `server/helpers/brute-knex.js`), which its server makes when it first starts past the setup, on a new wiki in the same process as the setup: as soon as both exist, before the server listens (`server/master.js`). `connect-session-knex` 2.0.0 reports its table ready before it exists, so the server also waits for each table to appear, for up to 5 seconds; a table that appeared even later would be closed at the next start;
  - `pagesVector` and `pagesWords`, when an admin turns on the PostgreSQL search engine, which makes them then.

  A set-up wiki has 32 tables in `public`, all with row-level security (34 with the PostgreSQL search engine). Those roles then see no row; Wiki.js's own connection owns the tables, so row-level security does not limit it. It never turns row-level security off, touches no other table, and does nothing on a PostgreSQL without those roles. If it fails, Wiki.js logs a warning and starts anyway.
- `server/setup.js`, `client/components/setup.vue` and `dev/templates/setup.pug`, the setup (see "The first administrator"). The setup page also no longer asks about telemetry, which stays off whatever the request says, and suggests the page's own address as the site URL.
- `client/components/common/tofu-source-link.vue` (new), `server/master.js`, `client/themes/default/components/nav-footer.vue`, `client/components/login.vue`, `welcome.vue`, `not-found.vue` and `unauthorized.vue`: a **Source code** link on every page's footer, the sign-in page, a new wiki's welcome page and the not-found and not-allowed pages, signed in or not, and on the setup page. It opens `SOURCE_URL`, which the gallery sets to this pin's commit, else this fork's `tofu` branch.
- `server/app/data.yml`: the default logo is the wiki's own 256-pixel butterfly icon (`/_assets/favicons/android-chrome-256x256.png`), not the same butterfly on upstream's `static.requarks.io`, which every visitor's browser asked for. An admin's own Logo URL still wins.
- `client/components/admin/admin-utilities-importv1.vue`: the Wiki.js 1.x import (Administration > Utilities) connects to its Git repository with a username and password only. Its SSH mode, whose field took the contents of an SSH key, is gone: Tofu's safety check refuses a page that asks for one, so Tofu would not deploy the wiki at all. The Git storage module (Administration > Storage) keeps its own SSH settings.

## The first administrator

- Wiki.js 2's first visit opens a setup page that makes the administrator. On Tofu a new copy is online at a public address before its owner first opens it, so upstream's setup would let whoever finishes it first own the wiki.
- **In this copy the setup only finishes with the password saved as `ADMIN_PASSWORD`**, which becomes the administrator's password. Until one of at least 8 characters is saved, the page says that the wiki is waiting for its owner and what they have to do, has no Install button, and the server refuses to finish (403). A wrong password waits a second before its answer; ten in a row close the setup for 15 minutes (counted in memory, so a restart clears it).
- The owner: saves a password as `ADMIN_PASSWORD` on the app's Keys & settings page in Tofu, with Hide this value after saving on; deploys again; opens the copy, enters their email address and that password twice, keeps the suggested site URL and chooses Install; then signs in at `/login` with that email address and password.
- After the setup Wiki.js never reads `ADMIN_PASSWORD` again: changing or removing it changes nothing. The administrator changes their password in their profile.
- There is no sign-up to close. Wiki.js's own accounts are made by the administrator (Administration > Users); self-registration stays off until an administrator turns it on for a sign-in method (Administration > Authentication). Guests can read pages, upstream's default, which Administration > Groups > Guests changes.

## What works differently on Tofu

- **Offline.** No telemetry, no daily check for a newer Wiki.js, and no interface languages but English: Administration > Locale lists English only. `WIKI_OFFLINE=false` (then deploy again) turns on what upstream does online: languages downloaded from `graph.requarks.io`, daily, and its update check. Telemetry still needs an administrator to turn it on (Administration > Utilities > Telemetry). Administration > Contribute, upstream's page of ways to support the project, still asks `graph.requarks.io` for its list of sponsors when an administrator opens it.
- **Uploads are kept in the database** (`assetData`), up to 5 MB each by default (Administration > Security). The copy's `data/cache` and `data/uploads` folders are scratch space, made again after a restart.
- **Storage targets** (Administration > Storage) that keep files on the server's own disk, Local File System and the Git module's local clone, lose them at each restart. An off-site target (S3-compatible storage, Azure, SFTP, a Git remote) keeps a copy of the wiki elsewhere; Git sync clones again after a restart.
- **Mail**: none until the administrator enters their own SMTP server in Administration > Mail. Password resets and other emails wait for it.
- **More than one instance**: Wiki.js keeps its settings, navigation and rendered pages cached per server process, and tells its other instances about a change only in its HA mode (`HA_ACTIVE=true`), which needs PostgreSQL's LISTEN/NOTIFY, which a transaction pooler does not carry. If Tofu runs more than one instance, a change made through one can show late on the others, until they restart.
- Administration > System Info shows the database host as `localhost`: it reads the `db` section of `config.yml`, not `DATABASE_URL`.
- The server runs as root (see the `Dockerfile` above).

### First round (`pin/2026-10-25`)
